⚠
Priority fees statiques
Le bot envoie des transactions au tarif plancher sans consulter les conditions réseau en temps réel. En période de congestion, les transactions tombent ou se font systématiquement devancer. Première cause d'échec d'atterrissage — estimée responsable de 40-60% des transactions échouées.
CritiqueRustPython
⚠
Polling HTTP toutes les 3 secondes
3 secondes entre chaque fetch, c'est 7-8 blocs Solana d'intervalle (400ms/bloc). Les opportunités d'arbitrage significatives disparaissent en 1-3 blocs. Le bot arrive structurellement en retard sur toutes les opportunités courtes et ne capture que les spreads persistants, qui sont aussi les plus compétitifs.
CritiquePython
⚠
Paramètres figés dans .env
MIN_PROFIT_PCT et MAX_SLIPPAGE_PCT sont des constantes statiques. Aucune adaptation aux conditions de marché, à la volatilité, ni à la congestion réseau. Toute modification nécessite un SSH dans le VPS + redémarrage du service. Incompatible avec une supervision IA temps réel.
PythonInfra
⚠
Zéro supervision IA depuis l'extérieur
Pas d'interface pour qu'un agent puisse interroger l'état du bot, analyser les logs ou ajuster les paramètres sans accès SSH direct. Le bot est une boîte noire depuis l'extérieur, sauf les notifications Telegram basiques qui sont unidirectionnelles.
IAMCP
⚠
Exécution standard vulnérable au MEV
Sans Jito bundles, les transactions passent par le mempool standard et sont lisibles par les bots MEV. Les arbitrages les plus rentables (spread >0.3%) sont front-run à quasi 100% avant d'atterrir. Le bot ne capture que les miettes ignorées par les bots professionnels.

MCP Servers — Catalogue complet

01 Helius Enhanced RPC MCP Priorité 1 · V1

Premier MCP à intégrer, impact immédiat. Helius expose via son API des fonctions absentes du RPC Solana standard : estimation dynamique des priority fees, simulation de transaction avant envoi, et parsing enrichi des transactions. Intégré dans executor_bridge.py, il permet au bot de calibrer ses fees en temps réel avant chaque envoi.

Tools exposés
getPriorityFeeEstimate simulateTransaction parseTransaction getCompressionProof
Taux d'atterrissage estimé : de ~60% à ~90% sur les périodes de congestion modérée. Réduction des fees gaspillées sur transactions échouées.
# executor_bridge.py — intégration Helius MCP async def get_priority_fee(self, tx_b64: str) -> int: resp = await self.helius_mcp.call( "getPriorityFeeEstimate", {"transaction": tx_b64, "options": {"priorityLevel": "High"}} ) return resp["priorityFeeEstimate"] # microLamports
02 Jupiter Aggregator MCP (officiel) Priorité 1 · V1

Jupiter maintient un MCP server officiel qui expose l'intégralité de son API v6 via des tools structurés. Remplace les appels httpx manuels par un protocole typé. L'avantage principal est l'accès à dynamicSlippage — Jupiter calcule le slippage optimal en temps réel selon la profondeur du pool, éliminant la constante statique 0.5% inadaptée.

Tools exposés
quoteGet swapPost swapInstructionsPost programIdToLabel tokensGet
Slippage dynamique : économie estimée 0.1-0.2% par trade sur pools SOL/USDC liquides. Déblocage automatique du routage triangulaire multi-hop.
03 arb-control MCP (serveur custom Python) Priorité 1 · V2

Serveur MCP à construire avec le SDK officiel Python (pip install mcp). Il expose l'état interne du bot comme des tools appelables par n'importe quel agent MCP-compatible. Une fois branché sur Nexus (@AlaeddineAgent_bot) ou Claude directement, la supervision complète du bot se fait en langage naturel depuis Telegram, sans aucune intervention SSH.

Tools à implémenter
get_live_state get_session_stats get_recent_logs set_param pause_trading resume_trading force_dry_run get_opportunities get_pnl_curve
Supervision IA complète sans SSH. L'agent peut analyser les logs, ajuster les params, et redémarrer le bot depuis une commande Telegram en langage naturel.
# arb_control_mcp/server.py — squelette from mcp.server import Server import mcp.server.stdio server = Server("arb-control") @server.tool() async def set_param(name: str, value: float) -> dict: """Modifie un paramètre du bot en temps réel.""" ALLOWED = {"min_profit_pct": (0.05, 2.0), "trade_amount_sol": (0.01, 0.1)} lo, hi = ALLOWED[name] assert lo <= value <= hi bot_state.params[name] = value return {"ok": True, "param": name, "value": value}
04 Birdeye Analytics MCP Priorité 2 · V2–V3

Birdeye est le principal agrégateur de données on-chain Solana. Son API expose des données historiques de prix, volume, et liquidité des pools DEX avec une granularité tick-by-tick. Utilisé pour le backtesting engine (V4), le modèle ML de scoring (V3), et les rapports IA nocturnes enrichis de contexte marché.

Tools exposés
getTokenPriceHistory getTokenVolume getPoolLiquidity getTopTraders getOHLCV
Alimente le backtesting V4 et le modèle ML V3. Fournit à l'agent IA des données de contexte marché pour les bilans nocturnes enrichis.
05 DeFiLlama MCP (TVL & liquidité cross-protocol) Priorité 2 · V2

DeFiLlama maintient un MCP server officiel avec les TVL des protocoles DeFi, les données de yield farming, et les flux de liquidité cross-chain. Combiné avec les alertes whale de Solana Tracker, permet à l'agent IA de détecter des migrations de liquidité avant qu'elles n'apparaissent dans les spreads — un signal avancé de quelques minutes.

Tools exposés
getProtocolTVL getPoolYields getChainTVL getProtocolHistory
Signal avancé sur les migrations de liquidité. Permet d'anticiper l'ouverture de spreads avant qu'ils ne soient exploitables, et de les éviter quand ils se referment.
06 Telegram Bot MCP (wrapper notifications) Priorité 2 · V2

Wrapper MCP du bot Telegram existant. Centralise toutes les notifications dans un seul composant appelable par l'agent IA. L'agent peut composer des messages riches avec des charts PNG générés côté Python (matplotlib), envoyer des rapports structurés avec des tableaux, ou déclencher des alertes critiques avec priorité haute.

Tools exposés
send_alert send_report_md send_chart_image send_trade_summary get_recent_alerts
L'agent peut envoyer des rapports formatés avec graphiques directement depuis ses analyses. Unifie le canal de notification pour toutes les composantes du système.
07 VPS Operations MCP (Bash wrapper custom) Priorité 3 · V2

Serveur MCP minimaliste (50 lignes Python) qui wrappe des commandes systemd, des lectures de métriques système, et des opérations de déploiement sur le VPS. Permet à l'agent de redémarrer le service, lire les logs, checker la charge CPU, ou déclencher un git pull + cargo build + restart — sans exposer un accès SSH complet. Surface d'attaque réduite, chaque action est auditée.

Tools exposés
restart_service get_logs get_system_metrics deploy_update get_disk_usage
Zéro SSH pour les opérations courantes. L'agent peut déployer une mise à jour complète (git pull → cargo build → restart) depuis une commande Telegram.
08 Jito Block Engine MCP Priorité 3 · V3

Jito Labs expose une gRPC API pour soumettre des bundles de transactions atomiques et monitorer leur statut. Un MCP wrapper en Rust ou Python permet au bot de soumettre des bundles et vérifier leur inclusion. Indispensable pour la V3 : sans Jito, tous les arbitrages significatifs sont front-run par les bots MEV qui lisent le mempool standard.

Tools exposés
sendBundle getBundleStatuses getTipAccounts getInflightBundleStatuses
Protection MEV complète. Exécution atomique garantie en un seul bloc ou zéro frais. Débloque les opportunités >0.3% actuellement capturées à 100% par les bots professionnels.
09 PostgreSQL MCP (trades & analytics store) Priorité 3 · V2–V3

Wrapper MCP autour de la base PostgreSQL locale. Chaque trade est inséré avec tous ses attributs. L'agent IA peut requêter la base pour des analyses complexes : "quel est mon meilleur DEX les lundis matin", "quelles heures ont le plus fort spread moyen", "comparaison profit estimé vs profit réel par paire". Alimente aussi le dashboard web et le backtester.

Tools exposés
query insert_trade get_stats_by_hour get_pnl_curve get_dex_performance
Transforme les logs en actif analytique structuré. Alimente le modèle ML V3, le backtester V4, et les requêtes ad-hoc de l'agent IA pour l'optimisation de stratégie.

Utilisé à la demande, pas en boucle continue.
